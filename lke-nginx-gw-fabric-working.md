The key thing you’re missing:

**NGINX Gateway Fabric does NOT create a public LoadBalancer until you create a Gateway resource.** ([NGINX Documentation][1])

So your installation is actually correct.

Below is a fully working production-ready LKE + Gateway API setup that:

* creates the Linode NodeBalancer automatically
* serves `nginx.hashlabs.in`
* supports HTTPS
* works on current LKE
* uses Gateway API correctly

---

# 1. Install Gateway API

```bash
kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.5.1/standard-install.yaml
```

---

# 2. Install NGINX Gateway Fabric

```bash
helm install ngf oci://ghcr.io/nginx/charts/nginx-gateway-fabric \
  --namespace nginx-gateway \
  --create-namespace
```

Wait:

```bash
kubectl wait --timeout=5m \
  -n nginx-gateway \
  deployment/ngf-nginx-gateway-fabric \
  --for=condition=Available
```

---

# 3. Create GatewayClass

Create `gatewayclass.yaml`

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: nginx
spec:
  controllerName: gateway.nginx.org/nginx-gateway-controller
```

Apply:

```bash
kubectl apply -f gatewayclass.yaml
```

---

# 4. THIS STEP CREATES THE LINODE NODEBALANCER

Create `gateway.yaml`

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: nginx-gateway
  namespace: default
spec:
  gatewayClassName: nginx

  listeners:
    - name: http
      protocol: HTTP
      port: 80
      allowedRoutes:
        namespaces:
          from: All
```

Apply:

```bash
kubectl apply -f gateway.yaml
```

---

# 5. VERIFY NODEBALANCER CREATION

NOW run:

```bash
kubectl get gateway
```

You should finally see:

```text
NAME            CLASS   ADDRESS
nginx-gateway   nginx   139.xxx.xxx.xxx
```

OR:

```bash
kubectl get svc -A
```

You will now see a new autogenerated service:

```text
nginx-gateway   LoadBalancer
```

This is what triggers Linode NodeBalancer creation. ([NGINX Documentation][1])

---

# 6. Deploy NGINX App

Create `nginx-app.yaml`

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-app
spec:
  replicas: 2

  selector:
    matchLabels:
      app: nginx-app

  template:
    metadata:
      labels:
        app: nginx-app

    spec:
      containers:
        - name: nginx
          image: nginx:latest

          ports:
            - containerPort: 80

---
apiVersion: v1
kind: Service
metadata:
  name: nginx-service

spec:
  selector:
    app: nginx-app

  ports:
    - port: 80
      targetPort: 80
```

Apply:

```bash
kubectl apply -f nginx-app.yaml
```

---

# 7. Create HTTPRoute

Create `httproute.yaml`

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: nginx-route

spec:
  parentRefs:
    - name: nginx-gateway

  hostnames:
    - "nginx.hashlabs.in"

  rules:
    - backendRefs:
        - name: nginx-service
          port: 80
```

Apply:

```bash
kubectl apply -f httproute.yaml
```

# 10. Production HTTPS

Install cert-manager:

```bash
helm repo add jetstack https://charts.jetstack.io
helm repo update

helm install cert-manager jetstack/cert-manager \
  --namespace cert-manager \
  --create-namespace \
  --set crds.enabled=true
```

---

# 11. Create LetsEncrypt Issuer

`issuer.yaml`

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod

spec:
  acme:
    email: admin@hashlabs.in
    server: https://acme-v02.api.letsencrypt.org/directory

    privateKeySecretRef:
      name: letsencrypt-prod

    solvers:
      - http01:
          gatewayHTTPRoute:
            parentRefs:
              - name: nginx-gateway
                namespace: default
```

Apply:

```bash
kubectl apply -f issuer.yaml
```

---

# 12. Create Certificate

`certificate.yaml`

```yaml
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: nginx-hashlabs-cert

spec:
  secretName: nginx-hashlabs-tls

  issuerRef:
    name: letsencrypt-prod
    kind: ClusterIssuer

  dnsNames:
    - nginx.hashlabs.in
```

Apply:

```bash
kubectl apply -f certificate.yaml
```

---

# 13. Enable HTTPS Listener

Update `gateway.yaml`

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: nginx-gateway

spec:
  gatewayClassName: nginx

  listeners:

    - name: http
      protocol: HTTP
      port: 80

    - name: https
      protocol: HTTPS
      port: 443

      tls:
        mode: Terminate

        certificateRefs:
          - name: nginx-hashlabs-tls
```

Apply:

```bash
kubectl apply -f gateway.yaml
```

# Important Architecture Detail

NGINX Gateway Fabric architecture changed recently:

```text
Gateway resource
    ↓
Data plane created dynamically
    ↓
LoadBalancer service created dynamically
    ↓
Linode NodeBalancer created
```

That’s why installing the Helm chart alone never created the NodeBalancer. ([NGINX Documentation][1])

Community discussions also mention Gateway API controllers behave differently from old ingress-nginx controllers. ([reddit.com][2])

[1]: https://docs.nginx.com/nginx-gateway-fabric/install/helm/?utm_source=chatgpt.com "Install NGINX Gateway Fabric with Helm | NGINX Documentation"
[2]: https://www.reddit.com/r/kubernetes/comments/18kyhph?utm_source=chatgpt.com "Is there an equivalent Gateway API Nginx helm chart like ingress-nginx?"
